TeaHub
Backend · Go
  • Built a Go-based developer intelligence platform for analyzing GitHub repos through AI-assisted Q&A, semantic search, and architecture generation.
  • Engineered an incremental indexing pipeline for 1,000+ files, cutting repeated analysis from ~55ms to ~2.7ms per update — a 20× speedup.
  • Implemented GitHub OAuth, JWT sessions, SQL-level multi-tenant isolation, rate limiting, and a Dockerized CI pipeline with race-detection tests.
GoPostgreSQLGemini APIDockerGitHub OAuth
GitHub Case study +

Problem

Getting oriented in an unfamiliar codebase is slow — cloning it, guessing where things live, and re-reading files just to answer "where is X handled?" That ramp-up cost repeats every time a developer touches a repo they didn't write, whether it's a new hire, a contributor, or a maintainer returning to old code.

Solution

Sign in with GitHub, import a repo, and it's incrementally indexed with real static analysis. From there you can browse the file tree, search by meaning, generate a Mermaid architecture diagram, and ask grounded questions — every answer cites the specific files it's based on, so answers stay traceable back to real code instead of being a plausible-sounding guess.

Engineering

  • Incremental indexing pipeline across 1,000+ files — repeated analysis drops from ~55ms to ~2.7ms per update (20× speedup) by only reprocessing files that actually changed
  • Stdlib-only Go backend — hand-rolled HS256 JWT and GitHub OAuth instead of pulling in dependencies for something this size
  • Ownership isolation enforced at the SQL level, not just in application code, plus rate limiting and path-traversal-safe repo access
  • Hybrid search: keyword pre-filtering + LLM re-ranking rather than a vector database, trading a bit of recall for lower latency and zero extra infrastructure
  • Automated CI — tests, race detection, static analysis, and Docker builds on every push

Status

Deployed — Vercel (frontend) + Render (backend), with the indexing pipeline built to scale to larger repos without a full-database rebuild.

Way-FLOW
Full-Stack · AI
  • Built a full-stack AI workflow studio converting natural-language process descriptions into editable, executable, testable workflow graphs.
  • Designed a typed workflow DSL supporting 6 node types, conditional branching, graph validation, and deterministic simulation with execution tracing.
  • Integrated OpenAI for parsing/docs/test generation with a local fallback for zero-API-key execution, plus automated Vitest + Playwright testing.
React 19React FlowExpressPrismaPostgreSQL
GitHub Case study +

Problem

Turning a process like "when a support ticket comes in, classify it, notify Slack if urgent" into something runnable normally means either a rigid no-code tool or hand-written glue code. Neither option is great for quickly testing whether a workflow idea actually behaves the way you expect before wiring it into a real system.

Solution

Type the process as a sentence; an AI model (or a local keyword-based fallback that needs no API key) parses it into a structured directed graph of typed nodes — trigger, ai_classify, condition, action, delay, escalate — that you can edit visually. From there the graph can be simulated end-to-end, with every branch and decision traced, before it's ever connected to a live system.

Engineering

  • Typed workflow DSL across 6 node types with graph validation and conditional branching
  • React 19 + TypeScript + Vite frontend with a drag-and-drop canvas built on React Flow
  • Express/TypeScript API with Prisma ORM; PostgreSQL in production, SQLite for local dev
  • Deterministic, in-process simulation engine with execution tracing — no external calls during a run
  • OpenAI-backed parsing/doc/test generation, with a fully offline local-parser fallback
  • Automated testing with Vitest and Playwright

Deployment

Deployed on Vercel (frontend + hosted Postgres), with a Render configuration also available.

Word-Level ISL Recognition
Computer Vision · ML
  • Built a video-based Indian Sign Language recognizer using MediaPipe pose estimation to extract body and hand keypoints across 45-frame clips.
  • Trained an LSTM model on keypoint sequences (INCLUDE-50 dataset + self-recorded videos), reaching ~95% real-time accuracy on unseen test data — versus 5% for an earlier CRNN baseline.
  • Shipped as a lightweight web app with live-camera and video-upload inference, and a 2.3MB model footprint (vs. 323MB for the CRNN version).
MediaPipeLSTMPythonFlask
GitHub Case study +

Problem

India has an estimated one certified sign-language interpreter for every 20,000 deaf individuals, making everyday communication with non-signers difficult. Prior attempts at automated recognition either needed heavy, full-frame video models or failed to generalize past the exact training clips.

Solution

A system that takes a 2-3 second video, extracts pose/hand keypoints with MediaPipe, and classifies the signed word with an LSTM trained on sequential keypoint data — no full-frame video processing required. Working from keypoints instead of raw pixels made the model dramatically smaller and faster while actually improving accuracy on unseen signers.

Engineering

  • MediaPipe PoseNet extracts body + hand keypoints per frame; videos are normalized to a fixed 45-frame input window
  • LSTM architecture trained on keypoint sequences, replacing an earlier Time-Distributed CRNN model that underfit and performed poorly in real time
  • Training data combined the INCLUDE-50 dataset with self-recorded videos to address class imbalance
  • Flask web app plus standalone scripts for live-camera and file-based inference

Results

The LSTM model reached 78% train / 74.6% validation / ~95% real-time test accuracy, and cut model size from 323MB to 2.3MB versus the earlier CRNN approach.

Welfare Ops API
Backend Engineering · REST API
  • Built a multi-tenant welfare operations backend for managing organizations, volunteers, welfare cases, and field assignments with strict organization-level data isolation.
  • Implemented JWT authentication, refresh-token rotation, role-based access control, input validation, rate limiting, and audit logging for secure API operations.
  • Added PostGIS-based geospatial dispatch to find nearby available volunteers, plus Redis caching for frequently accessed volunteer and dashboard data.
Node.jsExpressPostgreSQLPostGISRedisDocker
GitHub Case study +

Problem

Welfare organizations need to coordinate cases, volunteers, and field operations while maintaining secure access to organization-specific data. A simple CRUD backend isn't sufficient when multiple organizations, different user roles, sensitive data, and location-based volunteer dispatch are all involved at once.

Solution

Welfare Ops API provides a centralized REST backend for welfare operations — organization management, volunteer management, case tracking, volunteer assignment, authentication, role-based permissions, and location-based volunteer discovery. Tenant-aware authorization keeps resources isolated between organizations while giving superadmins, admins, dispatchers, and volunteers different levels of access to the same system.

Engineering

  • Layered Express.js REST API using routes, controllers, middleware, services, and utility modules
  • JWT access tokens with refresh-token rotation and bcrypt password hashing
  • RBAC with four roles: superadmin, admin, dispatcher, and volunteer
  • Tenant isolation via organization_id scoping enforced in authorization middleware, not just application logic
  • PostgreSQL + PostGIS ST_DWithin geographic queries and indexes for nearby-volunteer search
  • Redis caching for volunteer lists and organization dashboard stats, with cache invalidation on writes
  • Audit logging for successful write operations — user, IP, action, and resource
  • Request validation, security headers, CORS, rate limiting, centralized error handling, and Swagger API docs
  • Jest + Supertest coverage for backend testing

Deployment

Fully Dockerized via Docker Compose, running three services — the Node.js API, PostgreSQL 16 with PostGIS 3.4, and Redis 7. The API is exposed locally on port 3001, with interactive Swagger docs at /api/docs. The repository includes a Dockerfile, Compose configuration, database migrations, seed scripts, environment configuration, and production-oriented security settings. There's no public live demo yet — it's designed to run locally through Docker.
